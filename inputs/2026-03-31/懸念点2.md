**前回の致命傷だった DB 欠落や状態矛盾はかなり解消されています。**
ただし、まだ **「完全な handoff 仕様」ではありません。**
残っている本質的な穴は次の4つです。

1. **API contract が未完成**
   response 未定義がまだ大量にあります。request 未定義の PATCH も残っています。

2. **auth の省略ルールが文書化されていない**
   多数 endpoint が auth 節なしです。今は他文書から推測できるだけです。

3. **join request の path parameter が `{id}` のまま**
   これは小さく見えて、contracts / client / backend でブレます。

4. **member 管理 API の「通知する」記述が enum / target_type と噛み合っていない**
   ここは現状のままだと仕様が閉じません。

以下、**そのまま反映できる完全な修正案**を出します。
今回は、前回みたいに余計な拡張は入れません。**今の仕様思想を壊さず、足りない部分だけを埋めます。**
