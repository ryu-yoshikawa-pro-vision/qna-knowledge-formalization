# 実装スコープ分解書

## 1. 目的

この文書は、unknown Codex が**どの順序で** full-stack 実装を進めるべきかを固定する。

実装順は dependency と user value の両方を考慮し、次の 7 slice に固定する。

## 2. Slice 1: 認証 / 参加

### 目的

ログイン、workspace resolution、workspace 作成、招待受諾、参加申請までを通す。

### backend

* auth callback / me / logout / refresh
* workspace resolution
* invitation preview
* workspace create
* invitation accept
* join request create / cancel

### web

* login
* workspace resolution
* invitation accept
* join request

### mobile

* login
* workspace resolution
* invitation accept
* join request

### 完了条件

* 初回ユーザーが workspace 作成まで進める
* 招待 token から preview を確認できる
* 招待されたユーザーが参加できる
* 未参加ユーザーが join request を送れる

## 3. Slice 2: ナレッジ閲覧 / 検索

### 目的

knowledge list / detail / bookmark / search を通す。

### backend

* `GET /api/knowledges`
* `GET /api/knowledges/{knowledgeId}`
* bookmark API
* tag suggest API

### web / mobile

* knowledge list
* knowledge detail
* bookmark list

### 完了条件

* formal knowledge を検索して詳細表示できる
* tag filter と bookmark が動く

## 4. Slice 3: ナレッジ投稿 / レビュー / 正式化

### 目的

direct post knowledge の create / edit / request review / review / formalize を通す。

### backend

* knowledge create / update / share / request review / draft visibility / archive / revoke formal
* knowledge review / formalize
* review queue
* comments / links の最低限

### web / mobile

* knowledge create
* knowledge edit
* knowledge detail の review action
* review queue

### 完了条件

* knowledge が `draft -> shared -> review_requested -> formal` を通る
* `changes_requested` 後の修正再申請が通る

## 5. Slice 4: 正式ナレッジ改訂

### 目的

formal knowledge から edit draft を作成し、review / apply まで通す。

### backend

* edit draft create / get / update / share / request review / draft visibility / reviews / discard / apply / revisions
* `knowledge_edit_draft_reviews`

### web / mobile

* edit draft create
* edit draft detail / edit
* apply flow

### 完了条件

* 元作成者が edit draft を作成できる
* reviewer / admin / owner が review できる
* admin / owner が apply できる

## 6. Slice 5: Q&A / ナレッジ化

### 目的

question / answer / accept answer / reopen / archive / knowledge 化を通す。

### backend

* question CRUD
* answer create / update / delete
* accept answer / reopen / archive
* question revisions / answer revisions
* Q&A 由来 knowledge create

### web / mobile

* question list / detail / create / edit
* answer submit / edit / delete
* accept / reopen / archive
* Q&A から knowledge 作成

### 完了条件

* `open -> resolved_locked -> open` が通る
* accepted answer snapshot が保持される
* Q&A から draft knowledge が生成される

## 7. Slice 6: コメント / リンク / 通知 / ブックマーク

### 目的

cross-cutting 機能を画面横断で仕上げる。

### backend

* comments create / update / hide
* links create / delete
* notifications list / read / read-all / unread-count
* bookmark list / add / remove

### web / mobile

* comments
* links
* notification list
* bookmark list

### 完了条件

* comment、mention、reply 通知が出る
* link 権限が role 通りに動く

## 8. Slice 7: 管理 / タグ / 履歴

### 目的

owner/admin 向け運営系を仕上げる。

### backend

* invitations create / revoke / resend / list
* join request approve / reject
* role change / owner transfer / member remove
* tags create / rename / merge / archive
* revisions read

### web / mobile

* member management
* tag management
* revisions screen

### 完了条件

* 招待再送が動く
* tag merge が knowledge / question / draft に反映される
* 履歴画面が辿れる

## 9. 実装順を守る理由

* auth / workspace がないと他 slice を試せない
* knowledge 閲覧が先にあると UI / API の骨格が固まる
* direct post の review flow が knowledge の主線
* formal edit draft はその上に載る
* Q&A は独立度が高いが、knowledge 化で knowledge flow に接続する

## 10. 着手時のチェック

各 slice の開始前に次を確認する。

* 対応する screen が `画面APIデータ対応表.md` にある
* 対応する API が `API概要設計書.md` にある
* 対応する table が `テーブル定義.md` にある
* 対応する acceptance が `受け入れ基準.md` にある
