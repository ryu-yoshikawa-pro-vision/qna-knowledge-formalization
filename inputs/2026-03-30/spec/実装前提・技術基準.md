# 実装前提・技術基準

## 1. 目的

この文書は、unknown Codex が full-stack 実装に入る前に固定すべき**技術前提と分担境界**を定義する。

この文書は source から導ける範囲でデフォルトを固定し、実装時に不要な再設計を避けるための基準線とする。

## 2. 固定する技術前提

### stack

* Web: `Next.js App Router`
* Mobile: `Expo Router + React Native`
* Shared language: `TypeScript`
* Repo shape: `monorepo`
* DB: `PostgreSQL`
* API style: `HTTP JSON API`

### repo layout

```text
/apps
  /web
  /mobile
/packages
  /contracts
  /api-client
  /domain
  /tokens
  /ui-web
  /ui-native
  /config
```

## 3. 共有境界

| package | 共有するもの | 共有しないもの |
| --- | --- | --- |
| `contracts` | request / response schema、enum、API 型、screen で使う DTO | component 実装 |
| `api-client` | fetch client、auth header / cookie handling、error mapping | screen 固有 state |
| `domain` | usecase、permission helper、state transition helper、formatter | framework 固有 hook |
| `tokens` | color、spacing、radius、typography、badge token | platform UI component |
| `ui-web` | web 専用 component | native UI |
| `ui-native` | native 専用 component | web UI |

原則:

* UI は共有しない
* business rule は `domain` へ寄せる
* API contract は `contracts` を正にする

## 4. auth transport

### web

* Google login 後にアプリ独自 session を発行する
* session は DB 管理の session record を発行し、cookie には session identifier のみを保存する
* Web は `HttpOnly + Secure + SameSite=Lax` の session cookie を使う
* SSR / route guard / API call は cookie 前提で扱う

### mobile

* Mobile は bearer token を使う
* access token は短寿命、refresh token は DB 管理で rotate する
* token 取得後は secure storage に保存する
* token の再発行は `POST /api/auth/refresh` を使う
* logout は current session / refresh token を無効化する

### fixed policy

* Web と Mobile で transport は分ける
* auth 後の domain / workspace resolution / permission contract は共通にする

## 6. rich text 方針

* `content_json` を正本とする
* `content_markdown` は表示 / 比較 / 検索用の派生保存とする
* backend は `content_json` と `content_markdown` の両方を受け取り保存する
* client は editor 実装差分があっても、API 契約では同じ field を送る

### 固定実装

* Web: `Tiptap`
* Mobile: markdown-first editor + `content_json` 変換レイヤ

補足:

* editor ライブラリ自体は domain 契約ではない
* 実装を変えても `content_json` / `content_markdown` の契約は崩さない

## 7. 検索方針

* MVP の検索は `PostgreSQL Full-Text Search + tag filter` を前提にする
* `searchable_text` は保存時に生成する
* knowledge のデフォルト検索対象は `formal` のみ
* タグ複数選択は AND
* アーカイブはデフォルト除外、明示フィルタで含める
* ranking は `title > summary > body > tag`、同点時は `updated_at DESC` に固定する

## 8. 通知方針

* product notification はアプリ内通知のみ
* push notification / Slack は対象外
* Web / Mobile とも同じ notification API を使う
* レビュー待ちは個別通知ではなく badge + queue で扱う
* 招待 / 再送は membership flow の transactional email を送る

## 9. platform 差分方針

### 共通

* screen responsibility
* API contract
* permission 判定
* state transition
* validation
* badge / status 名称

### Web 固有

* SSR / route middleware
* header navigation
* 管理画面の table layout

### Mobile 固有

* stack navigation / tab navigation
* secure storage
* compact list / detail layout
* keyboard / input / gesture 対応

## 10. testing baseline

* Backend: schema / permission / state transition / validation test
* Web: screen rendering / form validation / route guard / happy path
* Mobile: screen rendering / auth flow / list-detail-create flows
* Shared: contract test、domain usecase test

## 11. この文書で固定したこと

* full-stack handoff 対象
* monorepo 前提
* shared package 境界
* Web cookie / Mobile bearer token の auth transport
* Web は DB 管理 session cookie、Mobile は DB 管理 refresh token + bearer token
* Web は `Tiptap`、Mobile は markdown-first editor
* route と platform 差分の基本方針
* PostgreSQL FTS 前提の検索方針と `title > summary > body > tag` ranking
