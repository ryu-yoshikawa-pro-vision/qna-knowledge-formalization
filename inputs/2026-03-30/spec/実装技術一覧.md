# 実装技術一覧

## 1. 目的

この文書は、`spec/` に整理した業務仕様と handoff 資料を、**実際に実装するための技術選定**へ落とし込むための一覧である。

`実装前提・技術基準.md` が「どの方向で作るか」を決める文書であるのに対し、
この文書は「何を使って実装するか」を具体化する。

## 2. 採用ポリシー

* まずは `Next.js App Router + Expo Router + PostgreSQL` を中心に MVP を成立させる
* Web と Mobile で UI は共有しない
* 共有するのは `contracts / api-client / domain / tokens`
* 実装者が追加判断しないよう、MVP に必要な主要技術はこの文書で固定する
* 将来差し替えやすいものは package 境界で隔離する

## 5. 実装テーマごとに必要な技術

### 5-1. 認証 / 参加

* Google OAuth / OIDC
* Web session cookie
* Mobile bearer token + refresh token
* session / refresh token を保存する DB table
* `Expo AuthSession`
* `Expo SecureStore`
* 招待 / 再送のための transactional email provider

### 5-2. API / backend

* `Next.js Route Handlers`
* `Zod` request validation
* `Drizzle ORM`
* `PostgreSQL`
* 構造化 logging
* `notifications` を同期書き込みする service

補足:

* MVP では message queue は必須ではない
* 長時間 batch や push 配信は対象外

### 5-3. DB / search

* `PostgreSQL`
* `Drizzle Kit` migration
* `tsvector` または同等の FTS 検索列
* `GIN index`
* weighted ranking SQL

最低限必要な DB 実装:

* auth / session
* workspace membership
* knowledge / review / revision
* question / answer / revision
* comment / link / bookmark / notification

### 5-4. Web frontend

* `Next.js App Router`
* `TanStack Query`
* `React Hook Form`
* `Tailwind CSS`
* rich text editor
* route middleware / guard

### 5-5. Mobile frontend

* `Expo Router`
* `TanStack Query`

* `Expo SecureStore`

### 5-6. editor / content 変換

### 5-7. テスト / 品質

* lint / format

## 6. MVP での固定実装詳細

### 6-1. backend topology

MVP では backend を別 app に分けず、`apps/web` 内の Route Handlers で HTTP JSON API を提供する。

理由:

* `spec` の app 構成を増やさず実装できる
* Web と API の deploy をまとめやすい
* Mobile からも同じ endpoint をそのまま利用できる

将来 API 専用 app が必要になれば、Route Handlers の実装を `packages/domain` と service 層へ寄せてから分離する。

### 6-2. auth 実装

実装は次に固定する。

* Google 認証で ID token / code を server へ送る
* server 側で Google 検証を行い user を upsert
* Web は session ID を cookie に保存
* Mobile は短寿命 access token と長寿命 refresh token を発行
* refresh token は server 側で hash 化して保持する

### 6-3. search 実装

実装は次に固定する。

* `searchable_text` を保存時に更新する
* `title > summary > body > tag` の重みで ranking する
* `updated_at DESC` を tie breaker にする

### 6-4. rich text 実装

実装は次に固定する。

* Web は `Tiptap`
* Mobile は markdown-first editor
* API に送る shape は常に `content_json` と `content_markdown`
* converter は `packages/domain` または editor 専用 package に隔離する

## 8. 実装開始時の bootstrap 順

1. `pnpm workspace` と `Turborepo` を初期化する
2. `apps/web` と `apps/mobile` を作る
3. `packages/contracts`, `api-client`, `domain`, `tokens` を切る
4. `PostgreSQL` と `Drizzle` を接続し、migration 基盤を作る
5. Google login、session、refresh token、招待メール送信を実装する
6. knowledge / question の core entity と revision / review を実装する
7. search、notification、bookmark、admin を後続 slice で追加する

## 9. 今回固定した技術選択
