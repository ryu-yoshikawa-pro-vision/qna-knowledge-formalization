Design the detail and editing screen for a formal knowledge edit draft.

Goal:
Allow the original author to revise a formal knowledge item through a clearly separated editable draft.

Layout:
- Global app shell
- Strong status area near the top
- Original formal version reference panel
- Main editable draft area
- Clear separation between current formal content and draft proposal

Required content:
- Draft title and status
- Reference to the original formal knowledge item
- Editable fields similar to the Knowledge Create / Edit experience
- Summary, body, tags, context, and related structured fields
- Review-related status and readiness guidance

Required actions:
- Save Draft
- Share
- Request Review

Critical rule:
Do not visually merge the draft with the current formal version.
The current formal version must remain clearly identifiable as the active source of truth.

Design emphasis:
- Proposal-oriented
- Review-aware
- Clear separation between official content and in-progress revision
