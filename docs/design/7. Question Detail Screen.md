Use the existing DESIGN.md in this project as the source of truth.

Keep the same design system, spacing, typography, color rules, status badge rules, layout structure, component language, and enterprise SaaS tone established in previous screens.

This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.
Avoid social or community-platform styling.
Do not introduce playful UI patterns, engagement mechanics, or decorative visual trends.
Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the Question Detail screen.

Goal:
Allow users to read a question, understand its resolution status, inspect answers, and derive formal knowledge from the resolved discussion.

Layout:
- Global app shell
- Question header area
- Main content area with question body and answers
- Supporting sections for comments, derived knowledge, and history

Required content:
- Title
- Status badge
- Tags
- Creator
- Question body
- Related links
- Question comments
- Derived knowledge list
- Bookmark action
- History entry points

Critical answer design:
Separate answers into two clearly different sections.

Section A:
Answers fixed at resolution time
- Best answer
- Other answers that existed at that time
- These should feel stable and frozen as the resolved snapshot

Section B:
Follow-up answers after reopening
- These must be clearly shown as later additions
- They must not be visually confused with the original resolved state

Role-aware actions:
- Select best answer
- Reopen question when allowed
- Start knowledge derivation from the Q&A

Important prohibition:
Do not include comment UI for answers.

Design emphasis:
- Clear distinction between the question itself, the resolved snapshot, and later follow-up discussion
- Lower visual priority than Knowledge Detail, but still structured and serious
