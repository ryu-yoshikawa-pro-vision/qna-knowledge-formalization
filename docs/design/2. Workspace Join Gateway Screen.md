Design the workspace join gateway screen shown after login.

Goal:
Help the user understand whether a workspace exists for their domain and guide the next action clearly.

Create a structured gateway screen with clear branching states.

Required states:
1. No workspace exists
- Message explaining that no workspace exists yet
- Workspace name input
- Primary action to create a workspace

2. Workspace exists but user is not a member
- Workspace name
- Short explanation of current access state
- Primary action to request joining
- Secondary guidance if the user was invited separately

3. Invitation-based access available
- Workspace name
- Invited role
- Invitation status area
- Primary action to accept invitation

4. Already a member
- Confirmation state
- Primary action to continue to workspace

Design rules:
- Keep it lightweight and decisive
- Make branching logic visually obvious
- Use cards or clearly separated panels if needed, but keep the page calm and simple
- Do not over-design this screen
