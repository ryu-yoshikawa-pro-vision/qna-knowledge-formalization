# Screen Map

## 1. 目的

この文書は `docs/spec/` の 20 screen ID を主キーにして、design prompt、raw export、prototype route、主要 API / data / acceptance を 1 か所で追えるようにする manifest である。

## 2. Route Naming Rules

- 正規名は常に `screen_id` を使う
- `route_slug` は prototype file 名のための従属情報とする
- prototype file は `{route_slug}.html` で固定する
- `question.detail` の履歴は別 route を作らず、同一画面内 modal / side panel で表現する
- `admin.members` は `Members` / `Invitations` / `Join Requests` の 3 subsection を前提にする

## 4. Flow Coverage

- 初回参加:
  - `auth.login` → `workspace.resolution` → `knowledge.list`
- 招待受諾:
  - `admin.members` → `workspace.invitation_accept` → `knowledge.list`
- 直接投稿から正式化:
  - `knowledge.create` → `knowledge.detail` → `review.queue` → `knowledge.detail`
- 正式ナレッジ改訂:
  - `knowledge.detail` → `knowledge.edit_draft_create` → `knowledge.edit_draft_detail` → `review.queue` → `knowledge.detail`
- 質問からナレッジ化:
  - `question.create` → `question.detail` → `knowledge.create`
