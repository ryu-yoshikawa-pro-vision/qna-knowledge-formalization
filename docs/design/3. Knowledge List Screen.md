Use the existing DESIGN.md in this project as the source of truth.

Keep the same design system, spacing, typography, color rules, status badge rules, layout structure, component language, and enterprise SaaS tone established in previous screens.

This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.
Avoid social or community-platform styling.
Do not introduce playful UI patterns, engagement mechanics, or decorative visual trends.
Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the main Knowledge List screen for the signed-in desktop web app.

Goal:
This is the primary landing experience after joining the workspace.
Users should immediately feel that formal knowledge is the main value of the product.

Layout:
- Global app shell with top header and left sidebar navigation
- Page title and short page description
- Search area at the top of the content
- Filter bar below search
- List of knowledge cards

Required top-level UI:
- Search input
- Filters for formal only, include unreviewed, unreviewed only, source type, tags, updated date, creator, visibility
- Sort control prioritizing relevance and updated date

Each knowledge card should show:
- Title
- Summary
- Tags
- Status badges
- Updated date
- Creator
- Bookmark action

Important states:
- Formal knowledge shown by default
- Empty state when no formal knowledge exists
- Empty search result state with clear reset action
- Loading skeleton state
- Permission-safe neutral layout

Design emphasis:
- Knowledge discovery must feel primary
- High scanability
- Dense but not crowded
- Strong hierarchy in cards
- The page should feel like an internal knowledge index, not a feed
