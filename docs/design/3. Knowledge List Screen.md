Design the main Knowledge List screen for the signed-in desktop web app.

Goal:
This is the primary landing experience after joining the workspace.
Users should immediately understand that reusable formal knowledge is the main value of the product.

Layout:
- Reuse the existing global app shell exactly in style and structure
- Reuse the existing page header pattern
- Reuse the existing search bar and filter bar patterns
- Use the established card/list language from the Foundation screen

Required top-level UI:
- Page title and short supporting description
- Search input
- Filters for formal only, include unreviewed, unreviewed only, source type, tags, updated date, creator, visibility
- Sort control prioritizing relevance and updated date
- Knowledge results section

Each knowledge card should show:
- Title
- Summary
- Tags
- Status badges
- Updated date
- Creator
- Bookmark action

Required states:
- Formal knowledge shown by default
- Empty state when no formal knowledge exists
- Empty search result state with a clear reset action
- Loading skeleton state
- Permission-safe neutral layout

Critical rules:
- This must feel more important than the Question List screen will later feel
- Do not make it look like a social feed, forum homepage, or activity stream
- Do not invent a different card style from the Foundation screen
- Search and filters must feel structurally consistent with the Foundation screen
- Status visibility must be strong but not noisy

Design emphasis:
- Knowledge discovery is primary
- High scanability
- Dense but not crowded
- Strong hierarchy in cards
- Calm enterprise information surface
