Use the existing DESIGN.md in this project as the source of truth.

Keep the same design system, spacing, typography, color rules, status badge rules, layout structure, component language, and enterprise SaaS tone established in previous screens.

This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.
Avoid social or community-platform styling.
Do not introduce playful UI patterns, engagement mechanics, or decorative visual trends.
Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the Review Queue screen for reviewer, admin, and owner roles.

Goal:
Provide a clear operational work queue for review tasks.
This is not a notification center. It is a review work surface.

Layout:
- Global app shell
- Clear page title
- Filters and sorting at the top
- Main queue list below

Queue scope:
- Knowledge items under review
- Formal knowledge edit drafts under review

Each queue item should show:
- Title
- Item type
- Creator
- Updated date
- Tags
- Result type
- Status
- Whether it is direct post or Q&A-derived
- Whether change-request history exists

Filters:
- Normal knowledge vs edit drafts
- Creator
- Tags
- Sort by old/new
- Possibly status or source type if needed

Design emphasis:
- Calm urgency
- Operational clarity
- Easy prioritization
- Strong scanability
- Visually distinct from the general notifications screen
