This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.

Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the Knowledge History screen.

Goal:
Help users inspect the revision history of a knowledge item with strong traceability and clear chronology.

Layout:
- Global app shell
- Page header with current item context
- Revision list
- Selected revision detail area

Each revision entry should show:
- Revision number
- Editor
- Updated timestamp
- Edit summary
- State at that time

Detail area should support:
- Reading the selected revision snapshot
- Lightweight compare entry point
- Clear navigation back to current detail view

Design rules:
- Do not visually mix current canonical content with revision history
- Prioritize clarity over advanced diff tools
- This should feel like an audit trail, not a code review interface
