Use the existing DESIGN.md in this project as the source of truth.

Keep the same design system, spacing, typography, color rules, status badge rules, layout structure, component language, and enterprise SaaS tone established in previous screens.

This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.
Avoid social or community-platform styling.
Do not introduce playful UI patterns, engagement mechanics, or decorative visual trends.
Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the Member Management screen for admin and owner roles.

Goal:
Support operational management of members, invitations, and join requests in a quiet and efficient admin interface.

Critical layout rule:
Use a table-based admin screen, not a card-based management screen.

Structure:
Create a multi-section or tabbed admin view with:
1. Members
2. Invitations
3. Join Requests

Use tables as the primary presentation format.

Members table suggested columns:
- Name
- Email
- Role
- Membership State
- Join Date
- Actions

Invitations table suggested columns:
- Invited Email
- Invited Role
- Status
- Expiration
- Inviter
- Actions

Join Requests table suggested columns:
- Requester
- Status
- Request Date
- Comment
- Actions

Actions:
- Invite member
- Cancel invitation
- Resend invitation
- Approve join request
- Reject join request
- Change role
- Remove member
- Transfer ownership

Design emphasis:
- Table clarity
- Strong operational trust
- Readable row structure
- Careful destructive action handling
- Quiet and enterprise-like admin experience
