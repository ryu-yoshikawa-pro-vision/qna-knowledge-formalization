Use the existing DESIGN.md in this project as the source of truth.

Keep the same design system, spacing, typography, color rules, status badge rules, layout structure, component language, and enterprise SaaS tone established in previous screens.

This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.
Avoid social or community-platform styling.
Do not introduce playful UI patterns, engagement mechanics, or decorative visual trends.
Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the Tag Management screen for admin and owner roles.

Goal:
Support controlled governance of tags through rename, merge, and archive operations.

Critical layout rule:
Use a table-based admin screen, not a card-based layout.

Layout:
- Global app shell
- Page header
- Filter area
- Main tag management table

Suggested table columns:
- Tag Name
- Normalized Name
- Status
- Usage Count
- Creator
- Updated Date
- Actions

Required filters:
- Active
- Merged
- Archived

Required actions:
- Rename
- Merge
- Archive

Supportive context:
- Merge target information
- Representative content using the tag
- Signals that help admins avoid destructive taxonomy mistakes

Design emphasis:
- Operational clarity
- Quiet governance workflow
- Table readability
- Strong destructive-action safety
- This should feel like information architecture management, not content browsing
