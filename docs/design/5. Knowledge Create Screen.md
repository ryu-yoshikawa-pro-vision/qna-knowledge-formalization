Use the existing DESIGN.md in this project as the source of truth.

Keep the same design system, spacing, typography, color rules, status badge rules, layout structure, component language, and enterprise SaaS tone established in previous screens.

This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.
Avoid social or community-platform styling.
Do not introduce playful UI patterns, engagement mechanics, or decorative visual trends.
Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the Knowledge Create screen for direct posting.

Goal:
Allow users to create reusable knowledge directly in a structured but focused writing experience.

Layout:
- Global app shell
- Strong page title and short instruction
- Main editor area with supporting structured inputs
- Action area clearly separated from the body editor

Required fields:
- Title
- Summary
- Long-form body editor
- Result type selector
- Context text field
- Tag input with suggestions
- Visibility selector
- Draft visibility selector

Required actions:
- Save Draft
- Share
- Request Review

Supporting UI:
- Lightweight validation or readiness checklist
- Guidance for recommended tag count
- State area near the top of the page
- Clear distinction between ordinary save actions and review-related actions

Design emphasis:
- Writing should feel focused and calm
- This is not a chat composer
- This should feel like creating a durable internal knowledge asset
