Use the existing DESIGN.md in this project as the source of truth.

Keep the same design system, spacing, typography, color rules, status badge rules, layout structure, component language, and enterprise SaaS tone established in previous screens.

This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.
Avoid social or community-platform styling.
Do not introduce playful UI patterns, engagement mechanics, or decorative visual trends.
Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the Question List screen.

Goal:
Allow users to browse questions as a secondary discovery surface, clearly separate from the primary knowledge-first experience.

Layout:
- Global app shell
- Page header
- Search area
- Filter bar
- Question result list

Required controls:
- Search input
- Tag filter
- Status filters for open, resolved and locked, archived
- Sort control

Each question card should show:
- Title
- Tags
- Updated date
- Creator
- Status badge
- Whether a best answer exists
- Answer count
- Bookmark action

Design emphasis:
- This should feel secondary to Knowledge List
- Keep strong structure and readability
- Avoid making questions look like a chat feed or forum homepage
