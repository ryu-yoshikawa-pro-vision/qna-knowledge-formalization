Use the existing DESIGN.md in this project as the source of truth.

Keep the same design system, spacing, typography, color rules, status badge rules, layout structure, component language, and enterprise SaaS tone established in previous screens.

This product is knowledge-first, state-driven, role-aware, and operationally clear.
Knowledge has higher visual priority than Q&A.
Avoid social or community-platform styling.
Do not introduce playful UI patterns, engagement mechanics, or decorative visual trends.
Use a calm blue-based enterprise interface with strong readability and structured information hierarchy.

Design the Knowledge Detail screen.

Goal:
Support deep reading, status understanding, review context, and traceability for a reusable knowledge asset.

Layout:
- Global app shell
- Strong page header area
- Main reading column
- Supporting information and action areas that do not overpower the reading experience

Required content structure:
- Title
- Summary
- Status badges
- Tags
- Creator
- Last updater
- Last updated timestamp
- Last content author
- Result attributes
- Context section
- Long-form body content optimized for readability
- Related links section
- Comments section
- History entry point
- Origin section if this item is derived from Q&A
- Archive reason if archived
- Indicator when a previous formal version exists

Action design:
Show role-aware action areas, but keep them visually secondary to content.
Examples include:
- Edit
- Save changes
- Request review
- Approve
- Request changes
- Formalize
- Unformalize
- Archive
- Bookmark
- Comment

Critical rule:
Do not visually mix the current formal version with an edit draft.
If draft-related context is shown, it must remain clearly separate.

Design emphasis:
- Reading first
- Strong title and metadata hierarchy
- States must be immediately visible
- This screen should feel authoritative and trustworthy
