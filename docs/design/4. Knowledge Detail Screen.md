Design the Knowledge Detail screen.

Goal:
Support deep reading, status understanding, review context, and traceability for a reusable knowledge asset.

Layout:
- Reuse the existing global app shell exactly in style and structure
- Reuse the existing page header language, but adapted for a reading-heavy detail page
- Use a main reading column with supporting information and action areas
- Reuse the reading surface language established in the Foundation screen

Required content structure:
- Title
- Summary
- Status badges
- Tags
- Creator
- Last updater
- Last updated timestamp
- Last content author
- Result attributes
- Context section
- Long-form body content optimized for readability
- Related links section
- Comments section
- History entry point
- Origin section if this item is derived from Q&A
- Archive reason if archived
- Indicator when a previous formal version exists

Action design:
Show role-aware action areas, but keep them visually secondary to content.
Examples include:
- Edit
- Save changes
- Request review
- Approve
- Request changes
- Formalize
- Unformalize
- Archive
- Bookmark
- Comment

Critical rules:
- Do not visually mix the current formal version with an edit draft
- Do not let actions overpower the reading experience
- Keep metadata and state visibility strong and structured
- Reuse the same status badge language and button hierarchy from the Foundation screen
- This must feel like the authoritative center of the product

Design emphasis:
- Reading first
- Strong title and metadata hierarchy
- Immediate state clarity
- Trustworthy and stable enterprise knowledge surface
