# 1. ドキュメントの目的

本ドキュメントは、MVPで扱う主要状態管理対象について、

* 状態一覧
* 遷移元 / 遷移先
* 実行主体
* 遷移条件
* 遷移時の副作用

を定義する。

対象は次の6つです。

* `knowledge_items`
* `knowledge_edit_drafts`
* `questions`
* `answers`
* `workspace_invitations`
* `workspace_join_requests`

---

# 2. 共通原則

## 2-1. 状態は意味を持つ

状態は単なる表示用ラベルではなく、**編集可否・レビュー可否・通知・検索表示**に影響する。

## 2-2. 状態をまたぐときは副作用を伴う

例:

* `review_requested` への遷移でレビュー待ちバッジ対象になる
* `resolved_locked` への遷移で質問と既存回答が凍結される
* `applied` への遷移で正式ナレッジ本体が更新される

## 2-3. コメントと状態は分ける

コメントが付いたこと自体では状態を変えない。
**明示的な操作**だけが状態を変える。

## 2-4. 本文編集は状態に影響する

特に `review_requested` 中の本文編集は、そのままレビュー待ちを維持しない。
内容が変わったら、元の審査状態は無効になる。

# 3. `knowledge_items` 状態遷移

## 3-1. 状態一覧

* `draft`
* `shared`
* `review_requested`
* `changes_requested`
* `formal`
* `archived`

## 3-2. 状態の意味

### draft

作成中の下書き。
デフォルトは本人のみ閲覧。必要ならレビュー権限者共有。

### shared

ワークスペース内で共有されているが、正式レビュー待ちではない。

### review_requested

正式レビュー待ち。
レビュー待ち件数バッジ対象。

### changes_requested

レビュー差し戻し。
修正して再申請すべき状態。

### formal

正式ナレッジ。
検索のデフォルト対象。

### archived

アーカイブ済み。
通常検索では除外。

---

## 3-3. 遷移表

### `draft -> shared`

**実行者**

* 作成者本人

**条件**

* ナレッジ作成済み
* 本文あり

**副作用**

* `draft_visibility` は null にする
* ワークスペース内閲覧対象になる

---

### `draft -> review_requested`

**実行者**

* 作成者本人
* admin
* owner

**条件**

* タイトルあり
* 要約あり
* 本文あり
* `result_type` あり
* `context_text` あり

**副作用**

* レビュー待ち件数バッジ対象
* `draft_visibility` は無効化
* レビュー対象として扱う

---

### `shared -> review_requested`

**実行者**

* 作成者本人
* admin
* owner

**条件**

* タイトルあり
* 要約あり
* 本文あり
* `result_type` あり
* `context_text` あり

**副作用**

* レビュー待ち件数バッジ対象

---

### `review_requested -> changes_requested`

**実行者**

* reviewer
* admin
* owner

**条件**

* `request_changes` を明示
* 差し戻しカテゴリ指定
* コメント入力

**副作用**

* 投稿者本人へ通知
* 差し戻し理由保存
* `knowledge_reviews` を記録
* レビュー待ち件数対象から外れる

---

### `review_requested -> formal`

**実行者**

* admin
* owner

**条件**

* 投稿者以外の有効レビュー1件以上
* `review_requested` 条件を満たしている

**副作用**

* `formalized_by_user_id` 記録
* `formalized_at` 記録
* 投稿者本人へ正式化通知
* 検索デフォルト対象になる
* レビュー待ち件数対象から外れる

---

### `review_requested -> shared`

**実行者**

* 作成者本人

**条件**

* `review_requested` 中に本文編集した場合

**副作用**

* レビュー待ち状態解除
* レビュー待ち件数対象から外れる
* 再レビュー申請が必要になる

---

### `changes_requested -> shared`

**実行者**

* 作成者本人

**条件**

* 修正保存

**副作用**

* 再レビュー申請待ちの共有状態へ戻る

---

### `shared -> draft`

**実行者**

* なし

**備考**

* 通常運用では戻さない想定
* MVPでは不要

---

### `formal -> archived`

**実行者**

* admin
* owner

**条件**

* アーカイブ理由必須

**副作用**

* 通常検索から除外
* 投稿者本人へ通知
* `archived_at`, `archived_by_user_id`, `archive_reason` 記録

---

### `shared -> archived`

### `changes_requested -> archived`

### `draft -> archived`

**実行者**

* 作成者本人
* admin
* owner

**条件**

* アーカイブ理由必須

**副作用**

* 通常検索から除外
* 投稿者本人へ通知（本人以外がアーカイブした場合）

---

### `formal -> shared`

**実行者**

* admin
* owner

**意味**

* 正式取り下げ

**条件**

* 理由必須

**副作用**

* 検索デフォルト対象から外れる
* 正式状態解除ログを残す

---

# 4. `knowledge_edit_drafts` 状態遷移

## 4-1. 状態一覧

* `draft`
* `shared`
* `review_requested`
* `changes_requested`
* `applied`
* `discarded`

## 4-2. 状態の意味

### draft

編集中下書き。
`draft_visibility` により、本人のみかレビュー権限者共有かを決める。

### shared

共有された改訂案。
まだ正式レビュー依頼ではない。

### review_requested

正式に改訂レビュー待ち。

### changes_requested

差し戻し。修正して再申請が必要。

### applied

正式ナレッジへ反映済み。固定状態。

### discarded

破棄済み。履歴保持用。

---

## 4-3. 遷移表

### `draft -> shared`

**実行者**

* 下書き作成者本人

**副作用**

* レビュー権限者が見やすい共有状態になる

---

### `draft -> review_requested`

### `shared -> review_requested`

**実行者**

* 下書き作成者本人
* admin
* owner

**条件**

* タイトルあり
* 要約あり
* 本文あり
* `result_type` あり
* `context_text` あり

**副作用**

* レビュー待ち件数バッジ対象

---

### `review_requested -> changes_requested`

**実行者**

* reviewer
* admin
* owner

**条件**

* `request_changes` 明示
* 差し戻しカテゴリ + コメント

**副作用**

* 作成者本人へ通知
* `changes_requested_at` 記録
* `knowledge_edit_draft_reviews` を記録
* レビュー待ち件数対象から外れる

---

### `review_requested -> applied`

**実行者**

* admin
* owner

**条件**

* 投稿者以外の有効レビュー1件以上
* レビュー申請条件を満たす

**副作用**

* 正式ナレッジ本体を同じ `knowledge_item_id` で更新
* `updated_by_user_id` = 反映者
* `last_content_author_user_id` = 下書き作成者
* 旧正式版を `knowledge_revisions` に保存
* `knowledge_edit_draft_reviews` を記録
* 下書きは編集不可になる
* 投稿者本人へ正式化通知
* レビュー待ち件数対象から外れる

---

### `review_requested -> shared`

**実行者**

* 下書き作成者本人

**条件**

* `review_requested` 中に本文編集した場合

**副作用**

* レビュー待ち解除
* 再申請が必要になる

---

### `changes_requested -> shared`

**実行者**

* 下書き作成者本人

**副作用**

* 修正後、共有状態へ戻る

---

### `draft / shared / changes_requested -> discarded`

**実行者**

* 下書き作成者本人
* admin
* owner

**条件**

* 破棄理由必須

**副作用**

* `discard_reason`, `discarded_at`, `discarded_by_user_id` 記録
* 同じ正式ナレッジに対して、新しい下書きが作れるようになる

---

### `applied -> *`

**実行者**

* なし

**ルール**

* `applied` 後は再編集不可
* 終端状態

---

### `discarded -> *`

**実行者**

* なし

**ルール**

* `discarded` 後は再利用不可
* 終端状態

---

# 5. `questions` 状態遷移

## 5-1. 状態一覧

* `open`
* `resolved_locked`
* `archived`

## 5-2. 状態の意味

### open

未解決。回答受付中。質問本文編集可。

### resolved_locked

解決済み。
質問本文と確定時点までの回答は凍結済み。
ただし新規回答追加は可。

### archived

アーカイブ済み。通常検索除外。

---

## 5-3. 遷移表

### `open -> resolved_locked`

**実行者**

* 質問投稿者
* admin
* owner

**条件**

* ベストアンサー選定

**副作用**

* `accepted_answer_id` 設定
* `accepted_by_user_id` 設定
* `accepted_answer_snapshot_*` 保存
* `resolved_at` 記録
* 質問本文を凍結
* その時点までの全回答に `locked_at` / `locked_by_user_id` 設定
* 質問投稿者と採用回答投稿者に通知

---

### `resolved_locked -> open`

**実行者**

* 質問投稿者
* admin
* owner

**条件**

* 再オープン操作

**副作用**

* `accepted_answer_id` 解除
* `reopened_at`, `reopened_by_user_id` 記録
* 以前のベストアンサー情報は履歴として残す
* 過去に凍結済み回答は解凍しない
* 質問投稿者と以前のベストアンサー投稿者に通知

---

### `open -> archived`

### `resolved_locked -> archived`

**実行者**

* 質問投稿者
* admin
* owner

**条件**

* アーカイブ理由必須

**副作用**

* `archived_at`, `archived_by_user_id`, `archive_reason` 記録
* 投稿者本人へ通知（本人以外が操作した場合）

---

# 6. `answers` 状態遷移

回答は専用 state enum を持たず、
**通常 / 凍結 / 論理削除**をカラムで表現します。

## 6-1. 通常状態

* `locked_at IS NULL`
* `is_deleted = false`

## 6-2. 凍結状態

* `locked_at IS NOT NULL`
* `is_deleted = false`

## 6-3. 論理削除状態

* `is_deleted = true`

---

## 6-4. 遷移表

### 通常 -> 凍結

**実行者**

* システム処理

**トリガー**

* 対応する質問が `resolved_locked` になったとき
  その時点までに存在していた回答すべて

**副作用**

* `locked_at`, `locked_by_user_id` 記録
* 本文編集不可になる

---

### 通常 -> 論理削除

**実行者**

* 回答投稿者本人
* admin
* owner

**条件**

* 削除理由必須
* ベストアンサー回答ではないこと
* 凍結済み回答の場合、本人削除は不可。admin/owner のみ可

**副作用**

* `is_deleted = true`
* `deleted_at`, `deleted_by_user_id`, `delete_reason` 記録

---

### 凍結 -> 論理削除

**実行者**

* admin
* owner

**条件**

* 削除理由必須
* ベストアンサー回答でないこと
  または、先に質問再オープンによってベストアンサー解除済みであること

---

### 論理削除 -> *`

**実行者**

* なし

**ルール**

* 復元はMVPでは持たない

---

# 7. `workspace_invitations` 状態遷移

## 7-1. 状態一覧

* `pending`
* `accepted`
* `revoked`
* `expired`

## 7-2. 状態の意味

### pending

有効な招待。

### accepted

受諾済み。

### revoked

送信者側で取り消し済み。

### expired

期限切れ。

---

## 7-3. 遷移表

### `pending -> accepted`

**実行者**

* 招待先本人（招待メール一致でログインしたユーザー）

**条件**

* 招待トークン有効
* 期限内
* ログインメールと `invited_email_normalized` 一致

**副作用**

* `workspace_members` に追加
* `accepted_by_user_id`, `accepted_at` 記録
* membership log 作成

---

### `pending -> revoked`

**実行者**

* admin
* owner

**副作用**

* 招待リンク無効化
* membership log 作成

---

### `pending -> expired`

**実行者**

* システム処理

**条件**

* `expires_at` 超過

**副作用**

* 招待リンク無効化

---

### `accepted / revoked / expired -> *`

**実行者**

* なし

**ルール**

* 終端状態

# 9. 状態遷移と通知 / バッジの関係

## 9-1. レビュー待ち件数バッジ

対象:

* `knowledge_items.status = review_requested`
* `knowledge_edit_drafts.status = review_requested`

表示対象:

* reviewer
* admin
* owner

通知は飛ばさない。

---

## 9-2. 個別通知が飛ぶ遷移

### knowledge

* `review_requested -> changes_requested`
* `review_requested -> formal`
* `* -> archived`（自分の投稿）

### question

* `open -> resolved_locked`
* `resolved_locked -> open`
* 新規回答追加

### workspace

* 招待受信
* 参加申請提出（owner / admin）
* 参加申請承認 / 却下

### comment

* コメント投稿
* メンション
* 返信

# 10. 状態遷移で守るべき不変条件

## 10-1. 正式ナレッジは直接編集しない

`formal` 本体に対する直接本文編集は禁止。
改訂は `knowledge_edit_drafts` 経由。

## 10-2. 本人以外は本文編集しない

owner/admin/reviewer でも、他人作成の本文は編集しない。

## 10-3. review_requested 中に本文が変わったら、その申請は無効

`review_requested` 中の本文編集は `shared` へ戻す。

## 10-4. resolved_locked は「その時点の結論固定」

質問本文と確定時点までの回答は固定。
ただし新規回答追加は可。

## 10-5. applied / discarded / accepted / revoked / expired / approved / rejected は実質終端

再編集や逆遷移を基本的に許さない。

# 11. この状態遷移仕様で未表現だが実装時に必要なこと

* 各遷移APIの認可チェック
* 監査ログ生成
* revision自動作成
* 検索インデックス更新
* 通知作成
* バッジ件数再計算
* tag統合時の検索再反映

これらはAPI概要設計で扱う。
