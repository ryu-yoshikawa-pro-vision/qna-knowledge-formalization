# 権限マトリクス

## 1. ドキュメントの目的

本ドキュメントは、MVPにおける各ロールの権限を明文化し、以下を防ぐことを目的とする。

* 実装時の認可漏れ
* 画面ごとの操作可否の解釈ズレ
* 運用時の責任境界の曖昧化

---

# 2. 対象ロール

* `owner`
* `admin`
* `reviewer`
* `member`

補足:

* 上記 role は `workspace_members.membership_status = active` のメンバーにだけ適用する
* 未所属ログインユーザー、招待先本人、参加申請者は role ではなく actor として扱う

## 2-1. pre-membership actor

| actor | 説明 |
| --- | --- |
| `unaffiliated authenticated user` | ログイン済みだが active な workspace membership を持たないユーザー |
| `invitation target user` | 有効な招待 token を持ち、招待メール本人として受諾対象になっているユーザー |
| `join request applicant` | 自分名義の `pending` join request を持つユーザー |

---

# 3. 権限設計の原則

## 3-1. 本文責任は作成者本人

**他人が作成した本文・内容は、管理者でも編集しない。**

対象:

* ナレッジ本文
* 正式ナレッジ編集下書き本文
* 質問本文
* 回答本文
* コメント本文

管理者・オーナーが行うのは、あくまで運営操作である。

## 3-2. レビュー権限と運営権限は分ける

* reviewer は内容品質を見る
* admin / owner は運営・正式化・整理を行う

## 3-3. 正式ナレッジは組織資産

`formal` は個人の所有物ではなく、組織資産として扱う。
そのため、作成者本人でも勝手に下げたり消したりしない。

## 3-4. 可視性と操作権限は別

見えることと、操作できることは別である。
特に reviewer は、レビュー権限を持つが `admin_only` を閲覧しない。

| ------------------- | --------------: | --------------: | -------: | --------------: |

# 18. 役割ごとの要約

## 18-1. owner

できること

* すべての運営操作
* 正式化
* 正式取り下げ
* アーカイブ
* ロール変更
* オーナー移譲

できないこと

* 他人本文編集

## 18-2. admin

できること

* 招待 / 参加承認
* レビュワー任命 / 解除
* 正式化 / 取り下げ
* アーカイブ
* タグ統合
* コメント非表示化

できないこと

* オーナー移譲
* 管理者昇格
* 他人本文編集

## 18-3. reviewer

できること

* レビュー
* 承認
* 差し戻し
* 強い意味のリンク追加/削除

できないこと

* 正式化
* 招待
* 参加承認
* タグ統合
* アーカイブ
* 他人本文編集

## 18-4. member

できること

* 質問
* 回答
* ナレッジ作成
* コメント
* ブックマーク
* `related / derived_from` リンク

できないこと

* レビュー
* 正式化
* タグ統合
* 他人本文編集
* 運営操作

# 19. この権限マトリクスで固定された重要事項

* **管理者でも他人の作成物本文は編集禁止**
* **reviewer はレビュー専任**
* **formal は組織資産**
* **Q&Aは時点固定**
* **編集下書きは本人だけが作る**
* **レビュー待ちは reviewer / admin / owner の責務**
* **閲覧権限と運営権限は別**
