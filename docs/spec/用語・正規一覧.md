## 10. 命名ルール

* 文書上は singular 名で説明し、table / API resource は plural / endpoint 名を使う
* `knowledge` と `formal knowledge` を混同しない
* `knowledge edit draft` は `draft knowledge` と呼ばない
* `review_requested` と `changes_requested` は knowledge / knowledge edit draft 両方で同じ意味を持つ
* `resolved_locked` は質問状態専用
* `draft_visibility` は draft 系の可視性であり、通常 visibility とは別概念
* `membership_status` は DB の所属状態、`relationship_status` は API の参加導線判定に使う

## 15. API error code 正規名

* `UNAUTHENTICATED`
* `FORBIDDEN`
* `NOT_FOUND`
* `VALIDATION_ERROR`
* `STATE_CONFLICT`
* `ALREADY_EXISTS`
* `EXPIRED`
* `DOMAIN_MISMATCH`

運用ルール:

* 未認証は必ず `UNAUTHENTICATED` を使う
* `UNAUTHORIZED` は使用しない
* 認可失敗は必ず `FORBIDDEN`
* 入力不正は `VALIDATION_ERROR`
* 対象状態不一致、楽観ロック競合、再実行不能な状態差異は `STATE_CONFLICT`
* 一意制約違反や重複作成は `ALREADY_EXISTS`
* 有効期限切れは `EXPIRED`
* workspace 解決や招待受諾で domain 不一致の場合は `DOMAIN_MISMATCH`
